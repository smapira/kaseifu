## S13 — Undo の二重実行

```text
scenario_id: S13
title: "Undo twice"
priority: P0
test_level: E2E

question: "同じ移動を二度復元せず、二度目の対象と副作用を説明できるか"

preconditions:
  - "成功した move だけがジャーナルにある状態（1 件または複数件）"

inputs:
  - "(i) move 1 件の状態で undo --last 1 を 2 回"
  - "(ii) move 2 件の状態で undo --last 1 を 2 回"
  - "(iii) undo --last 3 を 1 回（成功 move が 1 件しかない場合）"

expected:
  - "(i) 1 回目で復元。2 回目は NothingToUndo、stdout 'nothing left to undo'、終了コード 0"
  - "(ii) 2 回目は「2 番目に新しい成功 move」を復元する（同じ move を二度は戻さない）"
  - "(ii) その場合、2 回目に選ばれた move の id を事前に記録し、undo 行の source/destination がその逆順であることを確認する"
  - "(iii) 1 件復元した後は break し、3 回の undo 行は作られない"
  - "どの分岐でも同一 move が 2 回復元されない（undone_at が 2 度書き換わらない）"

failure_conditions:
  - "同一 move が 2 回復元される"
  - "2 回目が「何もしない」と説明されながら実際は別 move を戻している（記録なし）"
  - "復元先が上書きされる"

observation_points:
  - "undo 行の operation / source_path / destination_path / undone_at"
  - "各 move 行の undone_at の遷移"
  - "CLI の 'restored:' / 'nothing left to undo' / 'undo failed:' の別"

evidence:
  - "src/storage/history.rs:140-154（最新の success かつ undone_at IS NULL を 1 件選ぶ）、130-137（mark_undone）"
  - "src/operations/undo.rs:38-46（対象選択）、122-124（元 move のマーク）"
  - "src/main.rs:427-431（--last のループと break）、446-453（メッセージ）"

existing_test: "tests/phase5_execute_test.rs:610-624（一部。単一 move のみ）"
status: DESIGNED
```

設計上の指摘 F-03: 原典の「二重実行 → 同じ移動を二度復元しない」は満たすが、2 回目の振る舞い（次の move を戻す）が明記されていない。期待を上記 (i)(ii)(iii) の 3 分岐に精密化した。

```text
  - "確率分布（--verbose の stderr 出力）"

existing_test: "なし（未カバー）"

```

リスク R6 との関係: 閾値近傍の反転は「バグ」ではなく入力の分散と閾値設計の相互作用である。したがって本シナリオの合否は判定の一致ではなく、**記録と説明が残ること**に置く。
