記述形式は v1.1 §5 のスキーマに、v1.2 §12 の要求（観測ポイント）と実装根拠を加えたもの:

## S01 — ファイル移動と Undo の一貫性

```text
scenario_id: S01
title: "Move and Undo consistency"
priority: P0
test_level: E2E

question: "移動と復元でデータと履歴の整合性が保たれるか"

preconditions:
  - "移動元 <tmp>/report.txt が内容 payload で存在する"
  - "移動先候補 <tmp>/Documents/Reports/ が空で存在する"
  - "ジャーナル data/kaseifu.db が存在しない（CWD 相対。src/storage/history.rs:16）"
  - "実行ディレクトリはジャーナルを作ってよい作業ディレクトリ（CWD 相対のため）"

inputs:
  - "AutoMove を満たす Jev 応答（confidence >= 0.85 かつ margin >= 0.40）"
  - "organize <tmp>/report.txt --execute"
  - "undo --last 1"

expected:
  - "移動後: <tmp>/report.txt は存在せず、<tmp>/Documents/Reports/report.txt が内容 payload で存在する"
  - "移動: ジャーナルに operation=move の行が 1 件、result=success、undone_at IS NULL"
  - "undo 後: <tmp>/report.txt が内容 payload で復元され、<tmp>/Documents/Reports/report.txt は存在しない"
  - "undo: ジャーナルに operation=undo の成功行が 1 件追加され、元の move 行の undone_at が非 NULL"
  - "内容: 移動前・移動後・復元後で sha256 が一致する"
  - "終了コード: 両コマンドとも 0。undo の stdout に restored: <path> 行（src/main.rs:439-443）"

failure_conditions:
  - "ファイル消失（source も destination も無い瞬間がある）"
  - "内容変更（sha256 不一致）"
  - "二重復元（同一 move が 2 回復元される）"
  - "履歴不整合（undo 行が無い / undone_at が NULL のまま / move 行が failure で記録）"

observation_points:
  - "ジャーナル: select operation,result,undone_at from operations order by rowid"
  - "ハッシュ: shasum -a 256 <source> を 3 時点で比較"
  - "ファイル数: <tmp>/Documents/Reports/ のエントリ数が 1 -> 0 と遷移する"

evidence:
  - "src/operations/mover.rs:79-107（verify -> record_pending -> rename -> mark_success）"
  - "src/storage/history.rs:83-110,113-137,140-154"
  - "src/operations/undo.rs:38-46,57-83,113-130"
  - "src/main.rs:420-455（undo の表示と終了条件）"

existing_test: "tests/phase5_execute_test.rs:413-445, 533-557（一部）"
status: DESIGNED
```

再現手順の粒度: (1) ハッシュ記録 → (2) `organize --execute` → (3) ジャーナル 1 行目の状態確認 → (4) `undo --last 1` → (5) ハッシュ再計算とジャーナル 2 行目確認。

設計上の注意: 実 CLI では AutoMove 判定に実 Jev が必要（`src/operations/organize.rs:97-98`）。Jev を差し替えられない環境では、ライブラリ経路（`execute_move` + `undo_last_move`）で同じ観測を行う段を並置する（v1.2 の「実装済み仕様と設計の区別」に従う）。
