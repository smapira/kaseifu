- status: open
- milestone: M3 - Workflow semantics
- next owner: implementer（ただし設計はオーナー判断待ち）
- blocker: 閾値と探索深さの裏付けデータが不足
- 出典: #27 / #28 のシナリオA実測（`/Users/bookair18/Desktop/stash`、130 ファイル、2026-11-09）と、オーナーの「今回は既定に入れない」判断
- 優先度: 低（既定の挙動を変えずに opt-in で追加できる）

## 現状

`cluster` は `R`（OS 標準フォルダ）配下の既存ディレクトリを探索しない。
#28 の確定表の規則 1（「既定・`R` 配下に一致する既存ディレクトリがある →` `R/<既存>`」）は未実装のままで、実装は規則 2–5 のみ。
そのため、既存の整理先があるファイルも `R` 直下（または `R/T` / `R/T/E`）に置かれる。

## 実測（2026-11-09、シナリオA）

- `Noto_Sans_JP/README.txt` は `~/Documents/kaseifu-snapshots/20261014-205502-vision-p5b` に score 1.00 で一致するが、現在は `~/Documents/README.txt` に平坦に置かれる（`pass`）。
- 他の 30 件は 0.06–0.35 で、`~/Documents/Ambient Context/Days/2026-09-23` のような日付フォルダに当たる。閾値なしで有効にすると誤着地が増える。
- 「1 件だけ 1.00、残りは雑音」という分布は、閾値が存在する証拠にならない。

## やること（候補）

- `--match-existing` を opt-in で追加し、既定の挙動は変えない。
- 探索範囲は `R` の直下 1 階層だけにする（下層を許すと日付フォルダ事故が再発する）。
- 採用条件は score >= 0.6 かつ（完全一致 or 同一親）などの強い根拠に限る（推奨値、要検証）。
- 一致しなかったときは現行どおり規則 2–5 に落とす。
- レポートに「なぜそこへ置いたか」を出す（一致先 / スコア / 根拠）。

## 受け入れ条件

- `--match-existing` 無しの既定挙動が現行と 1 ビットも変わらない（テストで固定）。
- 実データ相当のフィクスチャで、誤着地（日付フォルダ等）が 0 件であること。
- 一致した場合としなかった場合の両方が、テキスト / JSON の理由付きで説明される。

## 制約

- 新規 crate 依存なし。CC 16 以上を作らない。検証は隔離 HOME と `target/` 配下のサンドボックスで行う。
- 既定の `cluster` 出力を変えない限り、既存テストの書き換えは不要なはず。
