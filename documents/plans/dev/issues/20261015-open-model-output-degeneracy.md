# 残タスク: モデル出力の退化（ファイル名の音写・型名の出力）への一般防御

- status: open
- 出典: `documents/plans/dev/20261015-reviewer-ai-rename-p7.md` R4、`20261014k-ai-rename-p5b-vision.md` D6
- 優先度: 中（再現した形はふさいだか、一般則がない）

## 現状（実測）

- 既存の防御: ラベル丸写しの保留（`label_echo`）、ファイル名エコーの除去（`strip_redundant_extension`、プロンプトの「never the file name or its stem」）、危険名の保留、長さと空白の正規化。
- 実測で観測した退化:
  - **文書（PDF）で題名が元のステムの写し**: `THCO-COA-Non-Detect Updated.pdf` → 題名 `THCO-COA-Non-Detect_Updated`（実機セッション、2026-10-15）。提案は `2022-06-07_THCO-COA-Non-Detect_Updated.pdf` となり、**内容由来の題名が付いていない**。既存の防御がすり抜ける形（元名からの正規化差が `strip_redundant_extension` の比較に掛からない）。
  - フォルダで子の本文ではなく**ファイル名**を題名にする（例: 子 `note.txt` → 題名 `note.txt`）。
  - PDF 主体のフォルダで**モデル自身の型名**を出す（`KfSemanticPayload` 等）。子の抜粋を長い順に上位 4 件へ絞る規則で再現形は解消した。
- いずれも「同じ入力・同じ設定で毎回起きる」ものではなく、**非決定的**。

## やること

- 出力の妥当性検査を 1 箇所に集める（題名がファイル名・子のファイル名・型名・フィールド名と一致したら保留、など）を既存規則の再利用で作れるか検討する。
- 「保留」の理由文が利用者に意味のある説明になるようにする（内部名を出さない）。
- 一般防御で**正当な題名を弾かない**ことを確かめる（部分一致の誤検出を作らない）。

## 受け入れ条件

- 再現していた 2 例がテストで固定され、保留の理由が利用者向け文言である。
- 既存の文書・画像・動画・フォルダの正常系が不変（既存 795 テストが無変更で通過）。

## 制約

- 新規 crate 依存なし。CC 16 以上を作らない。モデル出力の内容そのものは制限しない（人物・属性の記述はモデルの責務という決定を維持）。

## 検証

- 合成入力で複数回実行し、タイトルの分布を記録（1 回の成功を根拠にしない）。
