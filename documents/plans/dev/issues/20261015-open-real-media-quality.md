# 残タスク: 実写真・実動画での命名品質評価

- status: open（素材の用意が必要）
- 出典: `documents/plans/dev/20261015c-ai-rename-p7.md` §9.4 / §9.5、`20261015e-ai-rename-p9-perf.md` §2
- 優先度: 高（機能はできているが、実データでの品質が未評価のまま）

## 現状

- これまでの検証はすべて**合成素材**（生成した PNG / MP4 / Markdown）。
- 合成クリップのラベルは分類器にとって曖昧で、題名にもその曖昧さが乗る（実測: 夕景が `ping_pong` / `ball` に寄る）。
- 実データでは「モデルが実際にどう名付けるか」が未計測。

## やること

- 評価用の実素材を**利用者が用意**する（プライバシー: 本ツールのテストは実写真を読まない方針。評価用のコピーを専用ディレクトリに置き、そのパスだけを使う）。
- 素材種別ごとに 10〜20 件で `kaseifu rename <dir> --recursive` のプロポーザルを集め、人手で「採用 / 保留 / 誤り」を付ける。
- 誤りの型（ファイル名音写・種別羅列・過度に一般的・事実誤認）を分類し、プロンプトか規則のどちらを直すべきかを決める。
- 結果は計画書に実測として残す（個人情報を含む素材のパス・内容は記録しない）。

## 受け入れ条件

- 種別ごとの採用率と誤りの分布が数字で残っている。
- 誤りの型ごとに「対応する issue」または「対応しない理由」が書かれている。

## 制約

- 実ファイルを移動・削除・改名しない（dry-run のみで評価する）。
- 素材の内容・パスをリポジトリに書かない。

## 検証

- 評価手順を再実行可能な形で `kaseifu-bench` には載せない（素材が手元にしかないため）。手順と集計の記録だけを残す。
