## 指摘事項

### 🔴 P-1 期待結果が原典のコピーでは反証不能（v1.2 §13 の要求違反）

- 対象: 全 Sxx（S01–S28）、全 Cxx
- 指摘: v1.2 §13 は「各シナリオに反証可能な期待結果」を要求する。原典の「適切なエラー処理」「安全に処理」は観測値ではないため、そのままでは Pass/Fail を決められない。
- 改善案: すべての `expected` を、(a) 終了コード、(b) ジャーナル行の有無と状態語（`pending` / `success` / `failure` / `undone_at`）、(c) ファイルの存在・内容・ハッシュ、(d) stdout/stderr のどちらに出るか、(e) `ファイル:行` の根拠、のいずれかで記述する。抽象語（「適切」「安全」）は期待文から排除する。
- 状態: **反映済み**（全シナリオに `expected` + `observation_points` + `evidence` を付与）

### 🔴 P-2 S21（`scan`）が現行実装と矛盾する

- 対象: S21、D01
- 指摘: `src/main.rs:268-280` の `handle_scan` は**バナー出力のみ**（`target banner only (no mutation, no discovery)`）。v1.2 §3 の「対象ファイルが走査される」「件数と処理対象の整合性」をそのまま期待にすると、常に Fail する（= 反証不能ではなく、実装と無関係な期待）。
- 改善案: S21 を「引数・出力・エラー契約 + 非破壊性」に再定義し、走査系の期待（ファイル集合、再帰、隠し、上限 100）は `inspect`（S26-02、`src/context/builder.rs:45` の `read_directory(.., 100)`）と `discover` / `classify`（S27）に移す。`scan` を拡張する場合は設計提案として分離記述する。
- 状態: **反映済み**（S21 を再定義、F-11 として記録）

### 🔴 P-3 S13（Undo 二重実行）の期待が副作用を隠す

- 対象: S13、D11
- 指摘: `src/storage/history.rs:140-154` は `ORDER BY rowid DESC LIMIT 1` で「最新の成功 move」を選び、`src/main.rs:427-431` は `--last N` 回繰り返す。したがって 2 回目の undo は「何もしない」ではなく**その前の move を戻す**。原典の「同じ移動を二度復元しない」だけでは、この意図しない復元を Pass にしてしまう。
- 改善案: 期待を「(i) 同一 move は 2 回復元されない、(ii) 成功 move が 1 件だけなら 2 回目は `NothingToUndo` で終了コード 0、(iii) 成功 move が 2 件以上なら 2 回目は次の move を復元し、その `operation_id` がジャーナルに記録される」の 3 分岐で記述する。
- 状態: **反映済み**（F-03 として記録し、S13 に 3 分岐を明記）

### 🟡 P-4 v1.1 §6 の対応表は事実ではない

- 対象: 成果物 5（既存テスト対応表）
- 指摘: 「対応候補の整理」なので、そのまま納品すると S03 が `phase4_jev_decision_test.rs` にあるように読める（実際は `tests/phase5_execute_test.rs:78-128`）。
- 改善案: `cargo test --all-targets --all-features` の実測（2026-10-13: 279 passed / 0 failed）と、テストバイナリ別の関数名一覧で置換し、`カバー済み / 一部 / 未カバー` の 3 値を付ける。「一部」は“メカニズムは緑だが実 CLI / 異常中断 / 既定値では未検証”を意味する定義を明記する。
- 状態: **反映済み**（`20261014d-existing-test-coverage.md`）

### 🟡 P-5 完了条件（公開 11 コマンド）との整合が未記述

- 対象: 成果物 6（カバレッジ表）
- 指摘: `--help` の実測は 11（+ 隠し `discover`）。`completions` は HEAD に存在しない。この 2 点を書かないと「11 種類すべて対応」の判定ができない。
- 改善案: カバレッジ表に `discover` を「隠し・デバッグ専用（対象に含める）」、`completions` を「未実装（C08 で設計のみ）」として明示し、`help` は擬似コマンドとして扱う。
- 状態: **反映済み**（F-06、カバレッジ表の対象列）

### 🟡 P-6 動画の扱いが未定義

- 対象: 成果物 7（未カバー領域）、S26/S27 の入力
- 指摘: `src/context/image_metadata.rs:52-60` は画像のみを対象とし、`mp4` / `mov` の処理は `src/` に存在しない。実測テストデータに MP4 が 2 件あるのに、シナリオが 1 件も無い。
- 改善案: 動画を**現状対象外である事実**として明記し（判定材料はファイル名 + Spotlight の文字情報）、(a) 対象に含めない判断、(b) 対象にする場合の追加シナリオ案（撮影日時・GPS が Jev に送られない、動画クエリのスコープ、大容量ファイルの安定性）を分けて記述する。
- 状態: **反映済み**（R7、§8、S26/S27 の観測ポイント）

### 🟡 P-7 `--format json` の非対応コマンドが未記述

- 対象: S09、S28、C07、カバレッジ表
- 指摘: 実測で `scan --format json` は `Scanning: /tmp` を stdout に出す。`organize` / `undo` / `watch` も同じ（`src/main.rs:268-280,307-361,402-433`）。JSON を期待するシナリオを書くと誤った Fail 判定になる。
- 改善案: 「JSON を出すのは `inspect` / `discover` / `classify` + `emit_report` 系（setup/auth/config/doctor）のみ」を契約として明記し、S09/S28 の観測ポイントから JSON 期待を外す。
- 状態: **反映済み**（F-07、R9）
